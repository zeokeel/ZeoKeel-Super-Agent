# 交互审计：从“第一次使用的小白”视角（2026-11-04）

- 方式：共同审计（3 份独立报告 + Lead 汇总），只读，未改代码：
  - [新手旅程](interaction-novice-audit.md)（conf-product）
  - [交互机制](interaction-mechanics-audit.md)（nih-ui）
  - [术语/心智模型](interaction-semantics-audit.md)（conf-domain）
- 对象：当前 post-fix 代码；截图 r2/r3（修复前）与 r4（当前 tester）。无显示器，未做真人/读屏/IME 实测。
- 约束：**不背历史包袱**。不假设现有 7 页导航、`工作区/会话/工单/Ticket` 词汇必须保留；按“一个非技术操作员能否独立完成事情”重新设计。

## 结论

产品骨架（超级Agent + 项目/工作区 + 监控 + 设置）方向对，诚实状态是强项。但交互层面仍是**“工程系统加了一个聊天框”**，不是“给同事用的 AI 桌面应用”：

- 7 个核心旅程中，**0 个可无文档完成**；2 个部分完成；5 个失败。
- 新手必须学习内部模型（工单/触发/评估/来源/transport/DWS），而 UI 又把内部模型直接暴露出来。
- 三个动作最致命：**提问/派活分不清**、**审批找不到/不能撤销**、**第一次配置走不通**。

## 二、术语/状态：同一个东西有 5 个名字

| 系统里的词 | 用户实际会说什么 | 建议（唯一词） |
| --- | --- | --- |
| 工作区 / workspace / 项目目录 / 沙箱根 | 项目、文件夹 | **项目** |
| 会话 / 工单 / Ticket / 任务 / 执行 | 一次对话 / 一件事 | **对话** + **任务**（对话里的工作） |
| 来源 / 通道 / channel / transport / profile | 连接、账号 | **连接**（高级里才写 transport/profile） |
| 触发 / 评估 / 消息 / 执行 | 通知、待办、运行记录 | **收件箱** / **记录**（技术细节进“诊断”） |
| 待处理 / 需要我处理 / 待审批 / 等你处理 / 待你处理 | 要我拍板的事 | **待你决定（N）**，全站唯一计数 |
| 我创建的 / 超级Agent 创建的 | 谁提的请求 | **请求人：你 / 飞书·张三 / 钉钉·李四 / GitHub** |
| 待开工 / 排队中 / 执行中 / 等你处理 / 已结束；等待触发/等待评审/等待回答/受阻/失败/投递失败；待处理/进行中 | 现在到哪了 | 任务 4 态：**待你决定 / 进行中 / 需要你 / 已完成**（失败作为“已完成·失败”或独立“已失败”） |
| DWS / larkws / app id / secret / 检查通道 | 连接飞书/钉钉 | **连接飞书/钉钉**；技术项折叠在“高级” |

现状：注意力计数有 **5 套词、3 个集合**；任务状态有 **4 套词表**；同一个 N 在不同页面差 1–3。新手无法建立稳定心智。

## 三、目标交互模型（无历史包袱）

### 信息架构（建议直接替换）
```
左侧：
  ＋ 新对话（主按钮）
  收件箱  (N 件待你决定)
  项目     (acme/webapp, acme/data…)
  最近对话
  ─────────
  设置
  诊断（默认折叠/隐藏；放 trigger/eval/log/transport）
```
- 删除主导航的 **消息 / 来源 / 触发 / 评估 / 执行**。
- **首页 = 超级Agent 对话**：上方最近对话，中央输入框，右侧/内联待办卡；不再叫“总览”。
- **项目页** = 项目头（名称、目录、用途）+ 对话列表 + 任务/交付物；工作区管理（重命名/删除）只在这里。
- **收件箱** = 唯一注意力入口：IM 请求、需要回答的问题、失败/阻塞；每项显示来源/谁/原话/建议动作，按钮“批准并开始 / 仅回复 / 忽略”，支持键盘、批量、撤销、总是允许。
- **记录** = 人类可读时间线（谁在哪个会话让你做了什么、结果如何）；技术 trigg/eval/policy 进诊断。
- **设置** = 模型、项目、连接、外观、高级；连接向导独立。
- 状态栏只留“问题/待决定/帮助”，版本/rev/Go/CGO/SQLite 移到关于/诊断。

### 关键流程（新手视角）
1. **首跑 3 步**：连接模型（OpenAI/DeepSeek/Ollama 预设 + 测试）→ 选项目文件夹（原生 picker + 扫描预览）→ 可选连接 IM（跳过）→ 直接进对话，给 3 个示例问题。
2. **输入框**：多行（Enter 换行、⌘/Ctrl+Enter 发送）；上方一个可见 **目标 chip**：“发给：超级Agent（聊天）”或“项目：acme/webapp（派活）”；可切换；发送后消息进入当前对话，不另建“工单”。
3. **对话**：流式、Markdown/代码、复制/重试/停止、历史、长回答可展开；任务作为对话里的卡片（计划/进度/交付物），不是跳到另一个页面。
4. **IM 消息**：自动进入收件箱为“待办”，点开看到完整上下文；批准后成为对话中的任务；拒绝/撤销可见。
5. **连接 IM**：选飞书/钉钉 → 扫码/设备码/浏览器授权 → 等待并自动检测 → 选监听范围（@我/指定群）→ 发测试消息 → 完成；DWS 检测安装/版本，给出复制命令/打开终端按钮；失败有重试和帮助。
6. **任务详情**：计划/步骤/文件/日志（默认人话，技术折叠）；可停止/重试/复制结果。

### 交互规范（行业基线）
- 每屏一个主操作；主按钮必须有明确动词；危险操作默认焦点在“取消”，支持 10s 撤销。
- 所有可点元素可 Tab 聚焦、Enter/Space 激活、有 focus ring、role/label；最小点击 28×28。
- 表单：必填 `*`、字段旁 inline 错误、Enter 提交、Esc 关闭并确认丢弃。
- 所有异步 >1s 有 spinner/阶段文案；成功/失败有 toast；窗口隐藏时系统通知/托盘 badge。
- 多行输入尊重 IME：组合输入期间 Enter 不发送。
- 全站统一“待你决定 N”一个计数、一个来源；不做隐式筛选（项目筛选用可见 chip + 一键全部）。
- 提供 ⌘N 新对话、⌘, 设置、⌘Enter 发送、⌘[ 返回、上下文菜单（打开/复制 #N/重命名/删除）、拖入文件夹建项目。
- 文本用用户语言；工程状态/接口名不出现在主 UI。

## 四、优先级

**P0（发布前）**：P0-1 输入目标/聊天派活模型 → P0-2 审批收件箱+通知+撤销 → P0-3 首跑验证/跳过 → P0-4 401 诊断 → P0-5 IM 授权向导 → P0-6 键盘/可访问性 → P0-7 会话/任务概念 → P0-8 表单机制。
**P1**：统一术语与 4 态；移除主 nav 的工程页；导航 back/breadcrumb/滚动恢复；toast/spinner/undo；桌面菜单/快捷键/窗口持久化；设置搜索/重置/未保存 guard；聊天多行/流式/Markdown/历史。
**P2**：会话预览/未读/置顶/搜索/右键；最近目录；i18n；多窗口；高对比/系统字号；数据导出。

## 五、应该从主 UI 拿掉的东西（无历史包袱）

- “工单/Ticket/会话就是工单/触发/评估/来源/通道/transport/profile/DWS/larkws/Policy/Decision/reason 码”。
- “等待运行时投影 <key>”“动作未接线：运行时未提供 XxxInterface”“本组表单随后续里程碑出现”。
- 状态栏的版本/rev/Go/CGO/SQLite；设置页的退出码/日志路径/health 原始事实（移到诊断/关于）。
- 主导航的“消息/来源/触发/评估”四个工程页；合并为收件箱/记录/设置›连接，技术页进诊断。
- 重复的注意力 badge（顶栏/侧栏/总览/来源各一套），统一为一个。

## 七、Persona 审计追加（2026-11-04，非技术用户实操推演）

独立的“小白 persona”审计（[interaction-persona-audit.md](interaction-persona-audit.md)）又找到三个比“聊天/审批打磨”更底层的 P0，必须排在前面：

### P0-A 首次配置是死胡同，而且错误不可修
- 向导只把“模型 + 工作区名称”作为开始条件，API Key 可空；填错 Key 后没有“设置 › 模型”页面，也没有测试连接/跳过/演示模式。
- 任务因无模型停住时，报告让用户去“设置 › 提示词旁边的模型配置”，**这个控件不存在**（`runtime/worker.go:262`）。
- 结果：非技术用户第一次就卡死，且无法在应用内修复。必须新增独立“模型”设置组 + 测试连接 + 跳过/演示模式 + 可恢复入口。

### P0-B 运行中的任务无法停止
- “执行”列表没有行内动作；文案说“动作在总览”。
- 总览只渲染 `NeedsPerson`（回答/评审/受阻/失败/投递失败），**运行中的 Ticket 不出现在总览**；`ActionsFor` 明明为 running 返回“停止”，但没有任何页面渲染它（`ui/overview.go`、`ui/execution.go`、`ui/actions.go`）。
- 结果：用户点“开始”后不能停，只能等；这是基础控制缺失。

### P0-C “在我的文件夹里干活”是假的
- Worker 的 cwd 是 `<stateDir>/work/ticket-N`（`runtime/prepare.go:142`），不是用户选择的工作区根目录；
- 但 system prompt 写“工作目录就是它的根目录”（`runtime/worker.go:561`），用户以为改的是自己的文件夹；
- 交付物从 ticket 目录扫描，面板没有“打开所在文件夹/复制路径”；默认 prepare 为空时，用户的文件夹根本没有被碰。
- 结果：Agent 说“完成了”，用户打开自己的目录什么都没有——这是最严重的信任破坏。必须二选一：
  A. 真的在项目根目录执行（危险，需要沙箱/确认/快照）；或
  B. 明确“Agent 在副本里工作”，提供“打开副本/应用回项目/导出交付物”的可见路径，并显示复制/同步状态。

### 追加 P1（persona）
- 消息页回放的是 `localAnswer` 模板，不是输入框上方的模型回答（两处答案不一致）。
- 批准/重试/停止没有 pending/成功态，批完行直接消失；错误被聊天回答抑制。
- 弹窗显示 32 位 ID（“回答 #…”/“停止 #…？”），列表却是 `#42`；删除报错露出 `ws_…` 和“工单”。
- 交付物行有“›”但不可点，无路径/打开/定位。
- 钉钉默认 DWS，但渠道卡仍要求 Stream 的 AppKey/Secret/RobotCode；飞书要求不可知的 `oc_…` 会话 ID；“检查通道”测的是已保存配置，不是刚输入的值；onboarding 仍 pin 长轮询。
- 以上 P0-A/B/C 应排在聊天多行/视觉打磨之前。
