# 交互语义审计：新手心智模型 vs 系统模型（read-only）

> 对象：当前工作树 UI/文案/投影/引擎生命周期；证据：`internal/ui/*`、`internal/view/*`、`internal/runtime/*`、README、design §13、截图 `/tmp/r2-*`、`/tmp/r3-*`、`/tmp/r4-*`。
> 判据：**新手不该先学内部模型**。每个用户词必须只映射一个对象/状态；不可见的工程概念不得出现在主界面。

## 0. 结论先行

1. **"会话=工单"不成立**：会话（conversation）被定义成"一条工作项"，既不是聊天记录，也不是可复用的上下文；IM 的原始对话在面板里不可见（只以"消息/触发"事件存在）。用户会期待"会话里能看历史、能继续聊"，实际点开是任务的执行记录。
2. **注意力计数有 5 套近似词、至少 3 个集合**：`待处理`（顶部，=待批准请求+待你决定任务）、`需要我处理`（总览，同一集合）、`待你批准`（总览分组）、`待审批 N`（来源页，仅 IM 请求）、`等你处理`/`待你处理`（执行/工作区，仅任务阶段）。同一个"N"在不同页面可以差 1–3。
3. **任务状态有 4 套并存词表**：bucket（待开工/排队中/执行中/等你处理/已结束）、stageWord（执行中/排队中/等待触发/等待你评审/等待你回答/已结束）、badge（等待回答/等待评审/受阻/失败/投递失败）、默认（待处理/进行中）。同一工单在不同页面换 2–3 个词。
4. **主界面大量泄漏工程概念**：Ticket/Trigger/Eval/Decision/Policy/reason 码、worker/执行器、transport/profile/listen kind/DWS/larkws、app id/secret、游标/轮询、Thread/own=、orchestrator，以及状态栏 `rev 7 · Go 1.27.3 · CGO=0 · SQLite 12.4 MB`。
5. **"超级Agent 创建的"没有意义**：它表示"请求来自外部来源（IM/GitHub）"，不是"agent 创建的"；所有任务的执行者都是 agent，创建者是提出请求的人。分组应当是"谁提的"。

## 1. 统一词表提案（用户词 → 对象/状态；删同义词）

| 用户词（唯一） | 含义（对象/状态） | 明确删除/合并的旧词 |
| --- | --- | --- |
| **我** | 这台机器的操作员（单人）。不显示 operator/Self/账号 | operator、Self、我创建的 |
| **超级Agent** | 唯一的 agent 身份。不显示 Router/Worker/Session/执行器/orchestrator | 执行器、Worker、主 Session、Executor |
| **项目** | 一个文件夹（git 仓库/数据目录/文档目录）+ 说明；agent 在这里干活。替代"工作区" | 工作区、Workspace、根目录（作为标题）、repo/data 原词 |
| **请求** | 外部（飞书/钉钉/GitHub/我）提出、**尚未成为任务**的一件事。状态只有：待批准 / 已处理 | 提案、待批、待审批、待你批准（作为对象名） |
| **任务** | 被批准（或我直接派）的一件事。编号 `#N`，只有一个状态：**待你决定 / 进行中 / 已完成 / 已取消** | 工单、Ticket、会话、待开工、排队中、等待触发、受阻/失败（降为原因） |
| **待办** | 唯一的注意力队列：待批准的**请求** + 待你决定的**任务**。全产品只允许一个计数：**"N 件待你决定"** | 待处理、需要我处理、等你处理、待你处理、待审批 N |
| **对话** | 消息发生的上下文（IM 会话 / GitHub 评论线程 / 面板对话），可点回原处 | 会话（当"任务"用时）、Thread、线程 |
| **记录** | "它看到了什么、做了什么"的人话时间线（合并原 消息+触发+评估，默认折叠技术细节） | 消息页、触发页、评估页（作为主界面） |
| **连接** | 飞书/钉钉/GitHub 的账号与接收状态：**已连接 / 需要你处理 / 已关闭** | 来源、Source、通道、启用/未启用/未检查/未监听、transport、DWS、larkws |
| **设置** | 项目 / 连接 / 执行 / 提示词 / 系统（诊断入口） | 部署、评估设置（作为页） |
| **诊断**（高级） | 触发、评估、Policy/规则版本、reason 码、执行器会话、health、CLI、游标 | 触发页、评估页、健康卡、状态栏技术信息 |

任务状态归一：**待你决定**＝需批准/回答/评审/解除受阻/重试；**进行中**＝含"排队、等待外部事件、正在干"；**已完成**＝ready/merged/closed/dropped；**已取消**＝人停止。原因用一句话显示（"在等飞书上的回复"／"上次失败，可重试"），不再造词。

## 3. 新手 IA 提案（导航/页面/空态）

- **首页（超级Agent）**：聊天输入 + "N 件待你决定" 列表（**请求在前、任务在后**，每行一句人话 + 一个主按钮）+ 最近完成 3 条。空态："现在没有需要你决定的事。说一句话派活，或连上飞书/钉钉让它自己接活。"
- **项目**（唯一作用域页）：项目卡（名称/说明/文件夹/连接健康一句话）+ 任务列表（4 状态筛选）+ 结果（交付物）。空态："这个项目还没有任务。点『新任务』，或在首页说一句话。"
- **记录**：单条人话时间线（谁在哪个对话说了什么 → 它做了什么 → 结果），默认无技术行；每行可展开「技术详情」（触发/评估/reason/Policy）。空态："还没有记录。连上飞书/钉钉，或说一句话试试。"
- **设置**：项目 / 连接 / 执行 / 提示词 / 系统（含诊断入口、日志、备份、退出码）。
- **诊断（高级，默认隐藏）**：原 来源/触发/评估 的技术视图 + 执行器/会话/游标/health。

## 4. 工程页的去向

| 页 | 新手该叫什么/去哪 | 处置 |
| --- | --- | --- |
| 消息 | 记录（人话时间线） | 改名+合并，默认折叠技术行 |
| 来源 | 设置›连接（状态卡：已连接/需处理/已关闭） | 移出主 nav；transport/app id/DWS 放"高级" |
| 触发 | 记录›技术详情 或 诊断 | 移出主 nav |
| 评估 | 诊断 | 移出主 nav（主界面只保留"为什么没接"一句人话） |
| 执行 | 首页/项目的任务列表 | 保留"任务"概念，不保留"执行"页名 |
| 设置›部署 | 设置›系统 + 诊断 | 合并 |

## 5. Top 10 文案/IA 改动

1. 全局统一一个计数与词：**"N 件待你决定"**（nav 徽标、顶栏、首页标题一致；分页只说"本页 M 件"）。
2. 删"会话"，改"任务"；任务状态压到 4 个（待你决定/进行中/已完成/已取消），其余变一句原因。
3. 工作区→**项目**；项目树只做导航，进入项目页才过滤；全局页永远全局，页头常驻"当前：全部项目"。
4. "超级Agent 创建的/我创建的"→**按请求人分组**（我 / 张三·飞书 / GitHub @lin），并显示来源对话链接。
5. 请求卡与任务卡统一动作模型：**批准→任务**（"批准后开工"）、**拒绝→不留**；批准后立刻出现在"进行中"，并（产品确认后）给请求人一条短回执。
6. 主界面去工程词：Ticket→任务、Trigger→消息、Eval/Decision/reason/Policy→（仅诊断）判断/规则/原因码、worker→执行器、transport→连接方式、游标/轮询→接收状态。
7. 状态栏只留"最近问题 + 待决定"；`rev/Go/CGO/SQLite/OS/arch` 移入 设置›系统。
8. 所有"未接线/等待投影：<key>"改成用户话术 + "查看诊断"链接；不把开发态错误标红在业务行。
9. 连接卡统一三态：**已连接 / 需要你处理（下一步动作） / 已关闭**；隐藏 DWS/Profile/Listen kind/AppKey 到"高级"，且按 transport 只显示相关字段。
10. 评估/触发页降级为"诊断"（默认隐藏，? 里可进），主界面回答"我该做什么、做到哪了、结果在哪"。
